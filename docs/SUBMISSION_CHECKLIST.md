# Final submission checklist

## Project and report

- [ ] Fill in the student, programme, institution, guide, and academic-year fields in [the project report](PROJECT_REPORT.md).
- [ ] Review the [architecture diagrams](architecture.md) against the final code and export them to images if the submission format requires it.
- [ ] Add the exact software versions and environment used for the final run.
- [ ] Create and document a representative set of documents and manually labeled evaluation questions.
- [ ] Run all retrieval methods on the same labeled questions and k; copy the saved values into the results table in the report.
- [ ] Replace discussion prompts with findings supported by the saved evaluation report. Do not claim statistical significance unless it has been tested.
- [ ] Proofread and export the report to the required format, such as PDF.

## Application and test evidence

- [ ] Install dependencies, apply migrations, and run the app in a local Python environment.
- [ ] Execute the [manual functional test cases](test_cases.md); record tester, date, versions, outcomes, and defects.
- [ ] Resolve high-priority failures or describe remaining known limitations accurately.
- [ ] Capture demonstration screenshots if required and follow the [demo guide](demo_guide.md).
- [ ] Verify another user cannot access the demo user's documents, extracted text, or reports.

## Packaging

- [ ] Confirm the submission archive includes source code, templates, requirements, and all Phase 6 documents.
- [ ] Exclude local databases, uploaded private documents, credentials, virtual environments, and cache files.
- [ ] Open the extracted archive in a clean folder and follow its README setup instructions.
- [ ] Check the institution's naming, formatting, citation, and submission requirements.
